# Accessibility of the kit's components (WCAG 2.1 AA)

From the Design plugin's `accessibility-review`, as acceptance criteria per component. Automated scans find about a
third of the problems; the keyboard pass and a screen reader find the rest.

Common: contrast 4.5:1 text and 3:1 borders and focus (the tokens are checked by `theme.test.ts`); `:focus-visible`
on every control; targets ≥ 44 px on a coarse pointer (`--touch`); nothing conveyed by color alone (a badge has
text; a light has its word); `prefers-reduced-motion` honoured.

| Component | Must |
| --- | --- |
| `Menu` | trigger `aria-haspopup="menu"` + `aria-expanded`; list `role="menu"`, items `role="menuitem"`, roving focus with ↑ ↓ Home End, Esc closes and returns focus to the trigger, Tab leaves |
| `Tooltip` | shows on hover and on focus; `role="tooltip"` linked by `aria-describedby`; never the only name of a control (use `aria-label` for icon buttons) |
| `Dialog` / `ConfirmDialog` | native `<dialog>` with `showModal` (focus trapped, page inert), `aria-label` = title, Esc closes, Enter confirms; focus starts inside, on the content: the control marked `data-autofocus`, else the first field of the body, else the footer's first button, and the «×» only when there is nothing else; a confirmation starts on its reason field, or on the safe button when `danger` |
| `Drawer` | `role="dialog"` with `aria-labelledby`, not modal on desktop (the grid keeps working), `aria-modal` on phones; Esc closes; the first field takes focus; the resize handle is a focusable `separator` with arrow keys |
| `RecordPicker` | `role="combobox"` + `aria-expanded` + `aria-controls` + `aria-activedescendant`; options `role="option"` with `aria-selected`; ↑ ↓ ⏎ Esc; Backspace on a chosen value clears it; results announced through the listbox |
| `DateInput` / `Calendar` | the text box is the labelled control (tests fill it with ISO); the calendar is `role="grid"` with roving focus, arrows move a day or week, PgUp/PgDn a month, Enter picks, `aria-current="date"` on today, `aria-selected` on the value |
| Grid | `<table>` with `scope="col"` headers and `aria-sort`; rows focusable one at a time (roving `tabIndex`), ↑ ↓ Home End PgUp PgDn, ⏎ opens, Space marks, action keys run `rowActions`; header drag also by Alt ← →; the ⋯ menu reachable by Tab; resize handle `role="separator"` |
| `Breadcrumbs` | `<nav aria-label>`, the current tramo `aria-current="page"`, the copy-link button named |
| `Toast` | `aria-live="polite"` region, `role="status"`, closes on its own and by a button; an action inside is a real button |
| Keys drawn beside an action | `KeyHint`, the keys in a confirmation, a menu item or a palette option are `aria-hidden`: the button keeps its own name («Guardar»); the `?` dialog lists every key with its description |
| `LiveReadout` | the figure is `aria-hidden` (it changes many times a second); a polite `role="status"` region speaks once the value rests («12.340 kg, Estable») or the signal is lost; the state is a word beside the light; the section is named by its label |
| `ShortcutBar` | `role="toolbar"` with a name; every action is a real button whose name is its label (the key is `aria-hidden`); a disabled action says why in its `title`; the keys are listed by the `?` dialog; function keys work while typing |
| `LineEntryGrid` | a named `<table>` with `scope="col"` headers; every editable cell is a field named after its column; ⏎ / Shift ⏎ walk the fields, ↑ ↓ change line, Esc drops the typed text, Ctrl/⌘ ⌫ removes the line (also a named button); the draft's hint is a `role="status"` |
| `DocumentPreview` / `PrintBadge` | the frame has a `title`; the print state is a word, never the color alone |
| `ConnectionStatus` / `DeviceStatus` | `role="status"`; state as a word beside the light or icon; a device's detail shows on focus as well as on hover (the chip is focusable when it has one) |
| `Timeline` | a named `<ol>` of days, each a heading and an `<ol>` of entries; the hour is a `<time dateTime>`; the icon is `aria-hidden` (the kind is a word); actions are real buttons |
| `Tabs` | a named `role="tablist"`; each tab a button `role="tab"` with `aria-selected`, the chosen one the only stop of the bar (roving `tabIndex`) and linked to its `role="tabpanel"` by `aria-controls` / `aria-labelledby`; ← → move and choose, wrapping at the ends, Home and End jump, a disabled tab is skipped; the panel is focusable so Tab reaches content without controls |
| `TreeView` | a named `role="tree"`; nodes `role="treeitem"` with `aria-level`, `aria-setsize`, `aria-posinset`, `aria-expanded` on branches only and `aria-selected` only when a node can be chosen; children in a `role="group"`; one node in the Tab order; ↑ ↓ Home End walk the rows on screen, → opens then enters, ← closes then goes to the parent, Enter or Space choose (or open and close when nothing can be chosen); the arrow and the icon are `aria-hidden`; a state in `trailing` is a word, not a color alone |
| `Sparkline` | `role="img"` with a required `aria-label` that says what the shape shows; the figure it summarizes stands beside it as text; the tone never carries the meaning alone |
| `Badge` / `Light` | text always beside the color; the dot is `aria-hidden` |
| Forms | `<label htmlFor>` on every control (the tests find fields by label), `aria-required` not the attribute (the kit validates), `aria-invalid` + `aria-describedby` to the error, `role="alert"` on the error |
